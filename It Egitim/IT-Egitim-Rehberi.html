Windows Server

Kurulumdan Active Directory yönetimine, DNS'ten Group Policy'ye kadar sunucu yönetiminin temelleri.

01
Windows Server Nedir? Temel Kavramlar
▶

Windows Server Nedir?

Windows Server, Microsoft tarafından geliştirilen ve kurumsal ortamlarda kullanılan bir işletim sistemidir. Normal masaüstü Windows'tan farkı; çok kullanıcılı yönetim, merkezi kimlik doğrulama, dosya/yazıcı paylaşımı ve uygulama barındırma gibi özelliklere sahip olmasıdır.

Yaygın Versiyonlar

Windows Server 2016, 2019, 2022. Kurumlarda en yaygın 2019 ve 2022 kullanılır.

Rol ve Özellik Farkı

Rol: Sunucunun ana işlevi (DNS, DHCP, AD). Özellik: Rolü destekleyen ek bileşen.

Temel Roller

RolNe İşe Yarar?
Active Directory DSKullanıcı, bilgisayar, grup yönetimi
DNS ServerAlan adı ↔ IP çözümlemesi
DHCP ServerIP adresi otomatik dağıtımı
File ServerOrtak klasör paylaşımı
Print ServerAğ yazıcısı yönetimi
Hyper-VSanallaştırma platformu
Windows Server, küçük ofisten büyük kuruma kadar her ölçekte kullanılabilir. İlk kuracağınız rol genellikle Active Directory'dir.
02
Active Directory — Kullanıcı ve Grup Yönetimi
▶

Active Directory (AD) Nedir?

Active Directory, şirketteki tüm kullanıcı hesaplarını, bilgisayarları ve kaynakları merkezi bir noktadan yönetmenizi sağlar. Bir kullanıcı "etki alanına" (domain) katılmış herhangi bir bilgisayardan kendi şifresiyle oturum açabilir.

Temel Kavramlar

  • Domain (Etki Alanı): Şirketin merkezi yönetim birimi. Örn: smartgunes.local
  • Domain Controller (DC): AD'nin çalıştığı sunucu. Tüm kimlik doğrulamaları buradan geçer.
  • OU (Organizational Unit): Kullanıcı ve bilgisayarları gruplamak için kullanılan klasör yapısı.
  • Grup: Ortak izinlere sahip kullanıcı koleksiyonu (Security Group / Distribution Group).
  • GPO (Group Policy Object): Kullanıcı/bilgisayarlara toplu ayar uygulamak için kullanılan politika.

Temel PowerShell Komutları

New-ADUser -Name "Ahmet Yılmaz" -SamAccountName "ahmetyilmaz" `
  -UserPrincipalName "ahmetyilmaz@smartgunes.local" `
  -AccountPassword (ConvertTo-SecureString "Parola123!" -AsPlainText -Force) `
  -Enabled $true

Get-ADUser -Filter * | Select-Object Name, SamAccountName, Enabled

Add-ADGroupMember -Identity "IT-Ekibi" -Members "ahmetyilmaz"

Disable-ADAccount -Identity "ahmetyilmaz"   # Hesabı devre dışı bırak

Get-ADComputer -Filter * | Select-Object Name, OperatingSystem
Domain Controller'ı doğrudan üretim ortamında değiştirmeden önce mutlaka test ortamında deneyin. Yanlış bir GPO tüm kullanıcıları etkileyebilir.
03
DNS ve DHCP Yönetimi
▶

DNS (Domain Name System)

DNS, alan adlarını IP adreslerine çeviren telefon rehberi gibi çalışan sistemdir. Tarayıcıya google.com yazdığınızda, DNS size 142.250.185.46 IP'sini verir.

Kayıt TürüNe İşe Yarar?Örnek
AAlan adı → IPv4 adresiserver.local → 192.168.1.10
CNAMEAlias (takma ad)www → server.local
MXMail sunucusumail.smartgunes.local
PTRIP → Alan adı (ters)192.168.1.10 → server.local

DHCP (Dynamic Host Configuration Protocol)

DHCP, ağa bağlanan cihazlara otomatik olarak IP adresi, subnet mask, gateway ve DNS bilgisi atar. Bu sayede her cihaza elle IP girmek zorunda kalmazsınız.

  • Scope (Kapsam): Dağıtılacak IP aralığı. Örn: 192.168.1.100 – 192.168.1.200
  • Lease (Kiralama): IP'nin kaç gün geçerli olacağı. Genellikle 8 gün.
  • Reservation (Rezervasyon): Belirli bir cihaza her zaman aynı IP'nin verilmesi (MAC adresine göre).
  • Exclusion: Dağıtım dışında bırakılan IP'ler (sunuculara genellikle statik IP verilir).
Sunuculara, yazıcılara ve ağ ekipmanlarına mutlaka statik IP verin ya da DHCP rezervasyonu yapın. IP değişirse bağlantı kesilir.
04
Group Policy (GPO) Yönetimi
▶

GPO Nedir?

Group Policy, Active Directory'deki kullanıcı ve bilgisayarlara toplu ayar, kısıtlama ve yapılandırma uygulamak için kullanılır. Tek bir GPO ile yüzlerce bilgisayara aynı ayarı uygulayabilirsiniz.

Yaygın GPO Kullanım Senaryoları

  • Masaüstü duvar kağıdını şirket logosuyla zorla
  • USB depolama cihazlarını engelle
  • Parola uzunluğu ve karmaşıklığı zorunlu kıl
  • Ekran koruyucu ve oturum kilidi süresi belirle
  • Belirli yazılımların kurulumunu engelle
  • Yazıcıları otomatik dağıt
  • Windows Update ayarlarını merkezi yönet

GPO Uygulama Sırası (LSDOU)

# GPO'lar şu sırayla uygulanır (sonraki öncekini ezer):
1. Local  → Yerel bilgisayar politikası
2. Site   → AD sitesine bağlı politika
3. Domain → Domain düzeyinde politika
4. OU     → Organizational Unit politikası (en spesifik)
GPO değişikliği anında uygulanmaz. Yeniden başlatma veya gpupdate /force komutu ile tetiklenebilir.
05
Dosya Sunucusu ve İzin Yönetimi
▶

Paylaşımlı Klasör ve NTFS İzinleri

Windows Server'da dosya paylaşımı iki katmanlı izin sistemi ile çalışır: Share (Paylaşım) İzinleri ve NTFS İzinleri. İkisi aynı anda uygulanır, daha kısıtlayıcı olan geçerli olur.

İzin TürüKapsamÖnerilen Uygulama
Share İzniYalnızca ağdan erişimde"Everyone - Full Control" ver, NTFS ile kısıtla
NTFS İzniHem yerel hem ağ erişimiGruplara göre ayrıntılı izin tanımla

En İyi Uygulama

  • İzinleri kullanıcılara değil, gruplara verin. Kullanıcıyı gruba ekleyip çıkarmak yeterli olur.
  • Least Privilege ilkesi: Kullanıcıya sadece işini yapacak kadar izin verin.
  • Düzenli olarak izin denetimleri yapın (kim neye erişebiliyor?).
Hiçbir kullanıcıya "Domain Admin" yetkisi vermeyin. Ayrı bir yönetici hesabı oluşturun ve sadece gerektiğinde kullanın.

Yedekleme, İzleme ve Bakım
▶

Yedekleme Stratejisi (3-2-1 Kuralı)

  • 3 kopya veri tutun
  • 2 farklı ortamda saklayın (disk + NAS)
  • 1 kopya uzak konumda (bulut veya farklı bina) olsun

Windows Server Backup ile Yedekleme

# Sunucu yöneticisinden Windows Server Backup özelliğini kurun
Install-WindowsFeature Windows-Server-Backup

# Kritik bileşenleri yedekle
wbadmin start backup -backupTarget:E: -include:C: -allCritical -quiet

Sunucu Sağlığını İzleme

  • Event Viewer: Sistem, Güvenlik ve Uygulama loglarını takip edin.
  • Performance Monitor: CPU, RAM, disk ve ağ kullanımını izleyin.
  • Task Manager / Resource Monitor: Anlık kaynak tüketimini görün.
  • Windows Admin Center: Web tabanlı modern yönetim arayüzü.
Kritik event ID'leri: 4625 = Başarısız giriş, 4740 = Hesap kilitleme, 1074 = Sunucu yeniden başlatma.

02
IP Adresleme ve Subnetting
▶

IPv4 Adresi Yapısı

IPv4 adresi 32 bit'ten oluşur ve nokta ile ayrılmış 4 oktet halinde gösterilir: 192.168.1.100. Her oktet 0–255 arasında değer alır.

Özel IP Aralıkları (RFC 1918)

SınıfAralıkYaygın Kullanım
A10.0.0.0 – 10.255.255.255Büyük kurumsal ağlar
B172.16.0.0 – 172.31.255.255Orta ölçekli ağlar
C192.168.0.0 – 192.168.255.255Küçük ofis / ev ağları

Subnet Mask ve CIDR

  • /24 → 255.255.255.0 → 254 kullanılabilir host
  • /25 → 255.255.255.128 → 126 kullanılabilir host
  • /16 → 255.255.0.0 → 65.534 kullanılabilir host
Ağ adresi (ilk IP) ve broadcast adresi (son IP) kullanılamaz. /24'te 256 IP var ama 254 kullanılır.

Temel Ağ Komutları

ipconfig /all          # Tüm ağ adaptörü bilgisi
ping 8.8.8.8            # Bağlantı testi
tracert google.com      # Paket yolunu izle
nslookup google.com     # DNS sorgusu
netstat -an             # Açık bağlantılar
arp -a                  # ARP tablosu (IP-MAC eşleşmesi)
03
Switch, VLAN ve Ağ Segmentasyonu
▶

Switch Nedir?

Switch, aynı ağdaki cihazları birbirine bağlayan Layer 2 cihazdır. MAC adres tablosunu tutarak trafiği sadece ilgili porta yönlendirir.

VLAN (Virtual LAN)

VLAN, tek bir fiziksel ağı mantıksal olarak birden fazla ağa bölmenizi sağlar. Böylece farklı departmanlar aynı switch'e bağlı olsa bile birbirini göremez.

VLAN 10 — Yönetim

Sunucular ve ağ ekipmanları. Sadece IT erişebilir.

VLAN 20 — Kullanıcılar

Ofis bilgisayarları. İnternet erişimleri var.

VLAN 30 — Misafir Wi-Fi

Sadece internete çıkar, iç ağa erişemez.

VLAN 40 — IP Kameralar

Güvenlik kameraları izole edilir.

VLAN segmentasyonu hem güvenliği hem performansı artırır. Misafir ağını mutlaka ayrı VLAN'a alın.
04
Firewall ve Güvenlik Duvarı Yönetimi
▶

Firewall Nedir?

Firewall, ağ trafiğini kural tabanlı olarak filtreleyen güvenlik cihazdır. Hangi trafiğin geçip hangisinin bloke edileceğini belirler.

Kural Türleri

  • Inbound (Gelen) Kural: Dışarıdan içeriye gelen trafik. Örn: 443 portuna (HTTPS) izin ver.
  • Outbound (Giden) Kural: İçeriden dışarıya giden trafik.
  • Default Deny: Tanımlı olmayan her trafik engellenir — en güvenli yaklaşım.

Önemli Port Numaraları

PortProtokolNe İçin?

RDP portunu (3389) internete doğrudan açmayın. VPN arkasında kullanın. Açık bırakırsanız brute-force saldırılarına hedef olursunuz.
05
VPN — Uzaktan Güvenli Erişim
▶

VPN Nedir?

VPN (Virtual Private Network), internet üzerinden şifreli bir tünel oluşturarak uzaktaki kullanıcıların şirket ağına güvenli bağlanmasını sağlar.

Site-to-Site VPN

İki ofisi sanki aynı ağdaymış gibi birbirine bağlar. Router-router arası kurulur.

Remote Access VPN

Evden çalışan kullanıcının şirket ağına bağlanması. OpenVPN, Cisco AnyConnect vb.

Yaygın VPN Protokolleri

  • IPSec/IKEv2: Hızlı, güvenli. Windows ve mobil cihazlarla uyumlu.
  • OpenVPN: Açık kaynak, esnek yapılandırma.
  • WireGuard: Modern, çok hızlı, basit yapılandırma.
  • SSL/TLS VPN: Tarayıcı üzerinden bağlantı. Fortigate, Palo Alto vb.
Uzaktan çalışanlar için VPN zorunlu hale getirin. VPN olmadan şirket kaynaklarına erişime izin vermeyin.
06
Ağ İzleme ve Sorun Giderme
▶

Sorun Giderme Adımları

  1. Fiziksel katman: Kablo takılı mı? LED yanıyor mu?
  2. IP adresi: ipconfig ile kontrol et. APIPA (169.254.x.x) alıyorsa DHCP sorunu var.
  3. Ping gateway: ping 192.168.1.1 — router'a ulaşıyor mu?
  4. Ping DNS: ping 8.8.8.8 — internete çıkıyor mu?
  5. DNS çözümleme: nslookup google.com — isim çözümlüyor mu?

Ağ İzleme Araçları

  • Wireshark: Paket analizi, trafiği detaylı inceler.
  • PRTG / Zabbix: Ağ cihazlarını, sunucuları ve servisleri izler, alarm üretir.
  • SolarWinds: Kurumsal ağ izleme platformu.
  • Ping Plotter: Latency ve paket kaybını görsel gösterir.

01
ITSM ve ITIL Nedir?
▶

ITSM (IT Service Management)

ITSM, IT hizmetlerinin planlanması, tasarlanması, sunulması, işletilmesi ve iyileştirilmesi için kullanılan yöntemler bütünüdür. Hedef: IT'yi bir maliyet merkezi değil, iş değeri yaratan bir hizmet olarak yönetmek.

ITIL (IT Infrastructure Library)

ITIL, ITSM için en yaygın kullanılan çerçevedir. Şu anda ITIL 4 versiyonu geçerlidir.

Servis Değer Zinciri

Plan → Geliştir → Tasarla → Tedarik → Teslim → Destek → İyileştir

4 Boyut Modeli

Organizasyon & İnsanlar · Bilgi & Teknoloji · Ortaklar & Tedarikçiler · Değer Akışları

ITIL sertifikası almak isteyen IT profesyonelleri için: ITIL 4 Foundation sınavı iyi bir başlangıç noktasıdır.
02
Incident Yönetimi (Olay Yönetimi)
▶

Incident Nedir?

Incident, planlanmamış bir hizmet kesintisi veya hizmet kalitesinin düşmesidir. Örn: Sunucu çöktü, e-postalar gitmiyor, kullanıcı sisteme giremiyor.

Incident Yönetim Süreci

  1. Tespit: Kullanıcı bildirimi, otomatik alarm veya monitoring
  2. Kayıt: Ticket oluştur, detayları belgele
  3. Sınıflandırma: Kategori ve öncelik belirle
  4. Atama: Doğru ekibe/kişiye yönlendir
  5. Araştırma & Tanı: Kök nedeni bul
  6. Çözüm: Geçici veya kalıcı çözüm uygula
  7. Kapama: Kullanıcıya onaylat, ticket kapat

03
Problem ve Change Yönetimi
▶

Problem Yönetimi

Problem, bir veya birden fazla incident'ın kök nedenidir. Incident yönetimi hizmeti hızla restore eder; problem yönetimi ise tekrar olmaması için kök nedeni ortadan kaldırır.

  • Reaktif: Incident olduktan sonra kök neden analizi yap
  • Proaktif: Incident olmadan trenddeki sorunları tespit et
  • Workaround: Kalıcı çözüme kadar geçici çözüm
  • Known Error: Kök nedeni bilinen ama henüz çözülmemiş problem

Change Yönetimi

Change (değişiklik), IT altyapısında yapılan planlanmış modifikasyonlardır. Amaç: değişikliğin iş sürekliliğini tehdit etmeden uygulanmasını sağlamak.

Değişiklik TürüAçıklamaOnay Gerekir mi?
Standard ChangeÖnceden onaylanmış, düşük riskli rutin işlerHayır (önceden onaylı)
Normal ChangeCAB onayı gerektiren planlanmış değişiklikEvet (CAB)
Emergency ChangeKritik bir sorunu çözmek için acil değişiklikEvet (hızlı onay)
CAB = Change Advisory Board. Değişikliği kim, ne zaman, nasıl yapacak ve geri alma planı (rollback) nedir? Bunlar olmadan change kapatılmaz.
04
SLA, OLA ve KPI Kavramları
▶

SLA (Service Level Agreement)

SLA, IT ekibi ile iş birimi (veya müşteri) arasında hizmet seviyesini tanımlayan anlaşmadır. Yanıt ve çözüm sürelerini, uptime hedeflerini içerir.

Temel Metrikler

  • MTTR (Mean Time to Repair): Ortalama onarım süresi
  • MTBF (Mean Time Between Failures): Arızalar arası ortalama süre
  • First Call Resolution (FCR): İlk temasta çözülen ticket oranı
  • Uptime: %99.9 = ayda ~43 dk kesinti; %99.99 = ayda ~4 dk kesinti

OLA (Operational Level Agreement)

OLA, IT ekipleri arasındaki iç anlaşmadır. Örn: Yazılım ekibi, altyapı ekibine "sunucu talebini 4 saatte karşıla" diyebilir.

SLA ihlali gerçekleştiğinde bunu gizlemeyin. Neden ihlal edildiğini belgeleyin ve tekrar olmaması için önlem alın.
05
Ticketing Sistemleri ve En İyi Pratikler
▶

Yaygın Ticketing Araçları

  • ServiceNow: Kurumsal düzeyde en yaygın ITSM platformu
  • Jira Service Management: Yazılım ekiplerine yakın yapı
  • Freshservice: Küçük/orta ölçekli şirketler için uygun
  • Zendesk: Müşteri destek odaklı
  • ManageEngine: Uygun fiyatlı kurumsal çözüm

İyi Bir Ticket Nasıl Yazılır?

MFA (Multi-Factor Authentication)

MFA, kimlik doğrulamayı iki veya daha fazla faktörle güçlendirir. Parola çalınsa bile hesaba girilemez.

  • Bilgi faktörü: Parola, PIN
  • Sahip olma faktörü: Telefon (SMS kodu, authenticator uygulaması)
  • Biyometri faktörü: Parmak izi, yüz tanıma

MFA Yöntemleri (Güvenden Zayıfa)

  1. 🟢 FIDO2 / Hardware Key (YubiKey): En güvenli
  2. 🟢 Authenticator uygulaması (Microsoft/Google Authenticator): Çok güvenli

  4. 🔴 SMS kodu: SIM swap saldırısına açık — mümkünse kullanmayın

01
E-posta Güvenliğinin Temelleri
▶

Neden E-posta Güvenliği Kritik?

Siber saldırıların %91'i e-posta ile başlar. Phishing, iş e-postası dolandırıcılığı (BEC) ve malware dağıtımı için e-posta birincil araçtır.

Üç Temel Güvenlik Kaydı

Hangi sunucuların sizin adınıza mail gönderebileceğini tanımlar.

DKIM

E-postanın yolda değiştirilmediğini dijital imzayla doğrular.

DMARC

SPF veya DKIM başarısız olursa ne yapılacağını belirler.

Gelen e-postaların hangi sunucuya teslim edileceğini belirtir.

02
SPF, DKIM ve DMARC Yapılandırması
▶

SPF Kaydı (DNS TXT)

# Microsoft 365 için SPF kaydı
v=spf1 include:spf.protection.outlook.com -all

# Birden fazla mail sunucusu varsa
v=spf1 ip4:203.0.113.10 include:spf.protection.outlook.com -all

# ~all = soft fail (spam'e düşer)  -all = hard fail (reddedilir)

DMARC Kaydı

# DNS'e _dmarc.sirket.com TXT kaydı ekle
v=DMARC1; p=quarantine; rua=mailto:dmarc@sirket.com; pct=100

# p=none → sadece raporla (başlangıç için)
# p=quarantine → spam'e gönder
# p=reject → tamamen reddet (en güvenli)
Başlangıçta p=none ile başlayın, raporları izleyin, sorun yoksa quarantine sonra reject'e geçin.

▶

BEC (Business Email Compromise) Nedir?

Saldırgan, yönetici veya tedarikçi gibi davranarak çalışanı para transferi veya hassas bilgi paylaşımına ikna eder. Teknik değil, sosyal mühendislik tabanlıdır.

01
IT Varlık Yönetimi (ITAM)
▶

ITAM Nedir?

ITAM (IT Asset Management), şirketteki tüm IT varlıklarını (donanım, yazılım, lisans) yaşam döngüsü boyunca takip etme sürecidir.

Donanım Envanteri

  • Her cihaz için: Seri numarası, model, alım tarihi, garanti bitiş, atanan kullanıcı
  • Varlık etiketi (barkod/QR) ile fiziksel takip
  • Yıllık fiziksel sayım yapın
  • EOL (End of Life) yaklaşan cihazlar için bütçe planı yapın

Yazılım Lisans Takibi

  • Kaç lisans satın alındı vs. kaç kurulum var?
  • Lisans sözleşmeleri nerede saklı? Yenileme tarihleri?
  • Kullanılmayan yazılım lisanslarını iptal edin
Lisans uyumsuzluğu (daha fazla kurulum yapma) yasal risk ve yüksek ceza doğurabilir. Microsoft, Adobe gibi şirketler denetim yapabilir.
02
TCO ve IT Bütçe Planlaması
▶

TCO (Toplam Sahip Olma Maliyeti)

Bir IT yatırımının sadece satın alma fiyatı değil, yaşam döngüsü boyunca toplam maliyetidir.

Maliyet KalemiÖrnek

Capex vs Opex

Capex (Sermaye)

Sunucu satın alma, donanım yatırımı. Bir kez büyük ödeme.

Opex (Operasyonel)

Bulut aboneliği, SaaS lisansı. Aylık/yıllık düzenli ödeme.

Buluta geçiş Capex'i Opex'e dönüştürür. Mali yönetim açısından avantajlı olabilir — büyük başlangıç yatırımı gerekmez.

BCP / Felaket Kurtarma

Orta → İleri Seviye
01
BCP ve DR Nedir?
▶

Tanımlar

BCP (İş Sürekliliği Planı)

Felaket sırasında ve sonrasında iş fonksiyonlarının nasıl süreceğini tanımlar. İnsanlar, süreçler, teknoloji.

DR (Felaket Kurtarma)

IT sistemlerinin felaket sonrasında nasıl restore edileceğini tanımlar. BCP'nin IT alt kümesi.

Felaket Türleri

  • Doğal afet (deprem, sel, yangın)
  • Siber saldırı (ransomware, DDoS)
  • İnsan hatası (yanlış silme, yanlış yapılandırma)
  • Donanım arızası (sunucu, disk, ağ)
  • Elektrik/internet kesintisi
  • Tedarikçi/bulut sağlayıcı kesintisi
02
RTO, RPO ve Kurtarma Stratejileri
▶

Kritik Metrikler

RTO (Recovery Time Objective)

Sistem ne kadar sürede ayağa kaldırılmalı? Örn: "Üretim sistemi max 4 saatte restore edilmeli"

RPO (Recovery Point Objective)

En fazla ne kadar veri kaybedilebilir? Örn: "Max 1 saatlik veri kaybı kabul edilebilir"

Kurtarma Stratejileri (Maliyete Göre)

StratejiRTORPOMaliyet
Backup & RestoreSaatler-GünlerSaatlerDüşük
Warm StandbyDakikalarDakikalarOrta

RTO ve RPO hedeflerini iş birimiyle birlikte belirleyin. IT tek başına karar vermemeli. "Ne kadar kesinti iş açısından kabul edilebilir?" sorusu iş birimin cevaplar.
03
DR Planı Yazma ve Test Etme
▶

DR Planı Bileşenleri

  • Kritik sistemler listesi: Hangi sistemler önce restore edilecek?
  • İletişim planı: Felaket durumunda kim kimi arar? Alternatif iletişim kanalı?
  • Rol ve sorumluluklar: Kim ne yapar?
  • Kurtarma prosedürleri: Adım adım sistem restore talimatları
  • Tedarikçi iletişim listesi: Acil durumda aranacak numaralar
  • Test takvimi: Planın ne sıklıkla test edileceği

DR Testi Türleri

  • Masaüstü Egzersizi: Senaryo üzerinden teorik pratik
  • Tam Kesinti Testi: Gerçekten üretimi kapatıp kurtarma
  • Paralel Test: DR ortamını üretime paralel çalıştır
Test edilmemiş DR planı, planı olmamaktan daha tehlikeli olabilir. Gerçek felakette plan yanlış olduğunu görürsünüz — o zaman çok geç.
04
Bulut ile Felaket Kurtarma
▶

Azure Site Recovery (ASR)

Şirket içi VM'leri ve fiziksel sunucuları Azure'a sürekli replike eder. Felaket anında saniyeler içinde Azure'da ayağa kaldırılabilir.

  • Failover: Üretim sistemini Azure'a taşı
  • Failback: Sorun giderildikten sonra şirket içine geri al
  • Replication: Sürekli değişiklikler Azure'a gönderilir (RPO: dakikalar)
DRaaS (DR as a Service) ile büyük altyapı yatırımı olmadan uygun maliyetli felaket kurtarma mümkün. Küçük/orta şirketler için idealdir.

KVKK / ISO 27001

Orta → İleri Seviye
01
KVKK — Kişisel Verilerin Korunması Kanunu
▶

KVKK Nedir?

6698 sayılı KVKK, Türkiye'de kişisel verilerin işlenmesini düzenleyen kanundur. AB'nin GDPR'ına benzer. IT olarak verilerin nasıl toplandığı, işlendiği ve korunduğundan sorumlusunuz.

Temel Kavramlar

  • Kişisel Veri: Kimliği belirli/belirlenebilir gerçek kişiye ilişkin her türlü bilgi (isim, TC, e-posta, IP adresi, fotoğraf)
  • Özel Nitelikli Veri: Sağlık, biyometri, din, siyasi görüş — ekstra koruma gerekir
  • Veri Sorumlusu: Verinin işlenme amacını belirleyen şirket/kişi
  • Açık Rıza: Kişinin verilerinin işlenmesine onay vermesi

IT'nin KVKK Sorumlulukları

  • Veri envanteri oluşturma (hangi veri, nerede, kim erişiyor?)
  • Teknik güvenlik önlemleri (şifreleme, erişim kontrolü, log)
  • Veri ihlali durumunda 72 saat içinde KVK Kurumu'na bildirim
  • Veri silme prosedürleri (ayrılan çalışan, süresi dolan veri)
KVKK ihlali durumunda 1 milyon TL'ye kadar idari para cezası uygulanabilir. Bazı durumlarda cezai sorumluluk da doğabilir.
02

Confidentiality (Gizlilik)

Bilgiye sadece yetkililerin erişmesi

Integrity (Bütünlük)

Bilginin doğruluğu ve tamlığının korunması

Availability (Erişilebilirlik)

Bilginin yetkililere her zaman erişilebilir olması

Sertifikasyon

Akredite bağımsız kuruluş tarafından denetleme ve sertifika

ISO 27001 Uygulama Adımları

  1. Kapsam tanımlama
  2. Risk değerlendirmesi
  3. Risk işleme planı
  4. Kontrollerin uygulanması (Ek A — 93 kontrol)
  5. İç denetim
  6. Yönetim gözden geçirmesi
  7. Bağımsız denetim ve sertifikasyon

  • İletişim: Modbus, DNP3, IEC 61850 protokolleri; Fiber, 4G, uydu
